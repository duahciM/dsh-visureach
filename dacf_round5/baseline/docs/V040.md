# Video Observer 0.4.0

## Install and run

On Windows, unpack the versioned npm tarball and register its `index.js` with DeepSeek Harness. Provide a Python with the requirements from the deployment manifest and FFmpeg and FFprobe from the same installation. Current dependencies include Node with `node:sqlite` (supported by the validated desktop runtime), Pillow, NumPy, OpenCV, and optional local OCR, Whisper and CLIP backends. Set `processLocks: false` only for a single-process installation without SQLite. To preserve deployment isolation, use a separate cache directory for this release.

The standalone transport uses `node mcp_stdio.js <config.json> <source-root>...`. Each stdio process starts one fresh source/evidence session. Place Python, FFmpeg, cache and optional asset paths in the operator-owned JSON config. It returns actual PNGs as MCP image content. The same tool implementation is used by the native desktop and stdio transports. Stdio has no network listener. Active session caches and source directories should be private to the operator.

## Evidence paths

`object_candidate` retains multiple exact source/ROI views, including recurrence, replacement and conflict candidates. `compare_object_views` compares these views through descriptors fitted and tested on disjoint point sets, with the target excluded from the background model. The PTS, regions, descriptor coordinates, fit, holdout and residual are retained via `evidence_detail`. Two samples supporting B without demonstrated A support constitute an XB proposal. A-supported residuals are separate XD proposals with their own scope. The data support sample-level image interpretation. Physical identity, physical replacement, camera/world pose, causality and contents of gaps are unresolved.

`state_chain` connects timed original references to candidate states and relations. It keeps the open gaps and points to older revisions which require review. `observation_review` checks cited scopes and shared original captures, flags stale dependencies and open disputes, and preserves revisions. `claim_verify` independently decodes original frame evidence. Text causation and contradictions in visual meaning require a separate reviewer.

`evidence_routes` exposes recorded time, nomination, relation, source reread, and previously computed OCR, ASR, subtitle, CLIP and comparison results. Shared-root and time links are navigation metadata, with their edge types and missing endpoints preserved. Tools keep native receipt and query access independent of them. Batching changes the amount of local decode work, not the frame selected or transmitted.

`objectObservation`, `stateMemory`, `linkedRetrieval`, `batchSourceDecode` and `processLocks` can be switched off independently. Earlier tools and per-dimension switches remain. Copy-backed ledgers and process locks cover local concurrent writers; cross-host and network filesystem coordination have not been validated.

`stream_contract.schema.json` describes an independent live receipt interface. Live ingestion, bounded buffering, retention policy, interrupted segment reconciliation and replay transport are pending. The offline interface remains available.
