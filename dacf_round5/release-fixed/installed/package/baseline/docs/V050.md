# Video Observer 0.5.0

Install the versioned tarball and register `index.js` with the DeepSeek Harness plugin loader. Node requires `node:sqlite` for process coordination and the live read-only database. Use Node 24 or the tested Electron runtime, Python 3.12 or later with NumPy, Pillow and OpenCV, and FFmpeg/FFprobe from the same distribution. Configure `pythonPath`, `ffmpegPath` and `cacheDir` explicitly when outside the local development environment. OCR, ASR and CLIP have optional independent dependencies. The dormant 0.3 and 0.4 bundles and stores can be retained separately.

`observer_guide` returns an optional overview, selected tool example or workflow topic. The brief video-open introduction is the only injected overview. Each example needs real source PTS or receipt IDs from prior results. See `guide.js` and the executed release acceptance report. `compare_object_views` distinguishes `reference_a` and `reference_b` from `samples`; legacy ordered `prototypes` plus `ab_comparison` still works. Invalid A/B requests return typed recovery. `object_candidate` can look up all six IDs as source-local view aliases. `state_chain` and comparison consume those aliases without physical identity propagation.

The original catalogue and source cadence remain independent of a session's new evidence. `relation_figure2` can compute both graph views from a received original and its chosen neighbors or ROI. Its registered result is time-indexed as session-incremental in `evidence_routes`. Off-catalogue source access and scope remain identical. Evidence descriptions can be mechanically checked for scope, shared roots, dependency, reasoned claims and declared omitted details. Visual correctness remains independently reviewable.

The offline index retains completed nomination windows and resumes after interruption. Only bounded window pixels are held for nomination. Exact-PTS seeking on longer sources checks the decoder's output timestamps and falls back to indexed forward decoding. The offline timeline still uses a whole file PTS probe. Changed source bytes are explicitly labeled on catalogue/wave reads; original readbacks refuse stale bindings.

## Independent live adapter

The private producer can simulate arrivals from an existing file. It publishes already-arrived PNGs with their original PTS and durable stream receipts. A separate DSH configuration uses `live_plugin.js` with `streamDb`; don't enable the offline source-opening tools in that live-only session. A standalone MCP reader can use the same `streamDb` config without authorized source-root arguments. Neither reader gets the source pathname or future timeline. Use `live_status`, `live_catalog`, `live_wave`, `live_read` when warranted. Explicit lost frames, resuming the producer, and an open future remain separate. The producer can replay and advance a committed same-source cursor. Network/camera adapters and multi-epoch changes remain future integration.

## Local evidence timeline

Run `node viewer.js <manifest.json> <session-ledger.jsonl>` and open the printed loopback URL. The timeline shows nominated and already delivered original frames, exact PTS, SHA-256 and crop parent pointers with native ROI overlay. The viewer is a separate desktop-browser surface; the Electron application chrome is unchanged. Data is served only on the loopback address under a per-launch URL. Choose only ledger and cache files you intend to view locally.
